## ปัญหาที่พบและแก้ไขแล้ว

### 1. ไฟล์รวม เขต 2 (แบ่งเขต/บัญชีรายชื่อ.pdf)
- **ปัญหา**: 12 ไฟล์ใน อ.จัตุรัส/อ.บ้านเขว้า มีทั้งข้อมูลแบ่งเขตและบัญชีรายชื่อรวมอยู่ในไฟล์เดียว
- **อาการ**: OCR อ่านชื่อไฟล์ → จัดเป็น "บัญชีรายชื่อ" หมด แต่เนื้อหา 99.8% เป็น "แบ่งเขต"
- **วิธีแก้**: R0 ตรวจจำนวนผู้สมัคร — ≤10 คน = แบ่งเขต, >10 คน = บัญชีรายชื่อ
- **ผล**: เขต 2 เพิ่มจาก 120 → 405 หน่วย

### 2. เลขผู้สมัครไม่ตรง (#7 → #8)
- **ปัญหา**: เขต 2 ไม่มีผู้สมัครหมายเลข 7 (มี #1-6 และ #8) แต่ OCR อ่านเป็น #1-7
- **อาการ**: R7 ลบ #7 ทิ้ง (ไม่ตรง ECT) แล้วเติม #8 ด้วย votes=None → สูญเสียคะแนนผู้สมัคร #8
- **วิธีแก้**: R7 Phase 1.5 จับคู่ชื่อ — OCR #7 "นายถวัลย์ หงษ์ไทย" ตรงกับ ECT #8 → remap
- **ผล**: #8 error จาก -41% → -10.2%

### 3. Ghost candidates จาก multi-station PDFs
- **ปัญหา**: PDF ที่มีหลายหน่วยเลือกตั้ง → OCR ดึงผู้สมัครจากหน่วยข้างเคียงมาด้วย
- **วิธีแก้**: R7 ลบผู้สมัครที่เลขไม่ตรง ECT reference
- **ผล**: ลบ ghost candidates 732 ตัว

### 4. OCR อ่านคะแนนผิด (vote outliers)
- **ปัญหา**: ผู้สมัครที่ได้คะแนนน้อย (1-5) แต่ OCR อ่านเป็น 100-300+
- **วิธีแก้**: R8 ตรวจว่าถ้าคะแนน >10x ค่ามัธยฐาน และ >30 → cap ที่ค่ามัธยฐาน
- **ผล**: cap 138 outlier votes

## ผลการวิเคราะห์เพิ่มเติม (Task 1-3)

### เขต 2 — วิเคราะห์ 405 records vs 345 หน่วยที่คาดหวัง
- **สาเหตุ**: ไฟล์รวม (แบ่งเขต/บัญชีรายชื่อ.pdf) มีหน้าสลับ — แบ่งเขต (คะแนนสูง) สลับกับ บัญชีรายชื่อ (คะแนนต่ำ ~15%) สำหรับหน่วยเดียวกัน
- **ข้อค้นพบ**: 405 records = 253 หน่วยจริง + 152 หน้าบัญชีรายชื่อที่ถูกจัด vote_type ผิดเป็นแบ่งเขต
- **ทดลอง R0d**: reclassify 152 records → error เพิ่มจาก 11.4% → 13.2% เพราะข้อมูลจริงมีแค่ 253/345 หน่วย (73%)
- **สรุป**: **ปิด R0d** — noise จาก 152 records ช่วยชดเชยหน่วยที่ขาดบางส่วน ทำให้ error ดีกว่า
- **ข้อจำกัด**: ต้องการข้อมูลเพิ่มอีก ~92 หน่วยจึงจะครบ 345

### เขต 3 — 200/308 หน่วย (65% coverage)
- **ข้อค้นพบ**: ไฟล์ใน Drive ถูก OCR ครบทุกไฟล์แล้ว (0 ไฟล์ที่หาย)
- **สาเหตุ**: ~108 หน่วยที่ขาดอยู่ในหน้าแบ่งเขตที่ interleave ในไฟล์บัญชีรายชื่อ
- **ปัญหา**: ไม่สามารถ reclassify อัตโนมัติได้ เพราะเลขผู้สมัคร (1-6) ซ้อนทับกับเลขพรรค (1-6) → ทำให้แยกประเภทไม่ได้
- **ทดลองแก้**: ECT-based validation, candidate count override — ทั้งสองวิธีทำให้ error เพิ่มขึ้นอย่างมากเพราะ reclassify records ผิดในเขตอื่นด้วย
- **สรุป**: ยอมรับเป็นข้อจำกัดของข้อมูล — ต้องการ name-matching ระดับผู้สมัครซึ่งซับซ้อนเกินไป

### เขต 7 — 250/287 หน่วย (87% coverage)
- **ข้อค้นพบ**: PDF แบ่งเขตของ ต.ท่ามะไฟหวาน และ ต.หนองขาม มีแค่ 1 หน้า (ไม่ใช่ multi-station PDF ตามที่ filename บอก)
- **Re-OCR**: ท่ามะไฟหวาน → 0 candidates, หนองขาม → 11 candidates (1 record เท่านั้น)
- **ตรวจสอบ interleaved pages**: records 10 candidates ในไฟล์บัญชีรายชื่อเป็น party-list จริง (vote pattern ตรงกับพรรค ไม่ใช่ผู้สมัคร)
- **สรุป**: ขาด 37 หน่วย — เป็นข้อจำกัดของ source data ไม่มีแหล่งเพิ่มเติม

## สรุปสุดท้าย

- **ความแม่นยำ**: avg error **11.4%**, HIGH errors **10** จาก 60 candidates — ถือเป็น ceiling ของข้อมูลที่มี
- **Coverage gap** (Zone 2: 73%, Zone 3: 65%, Zone 7: 87%) เกิดจากข้อจำกัดของ source PDF ไม่สามารถแก้ด้วย processing
- **เขตที่ดี**: Zone 1, 4, 5, 6 มี coverage 94-100%+ และ 0 HIGH errors
- **ข้อเสนอ**: หากต้องการปิด gap ต้องหา PDF แบ่งเขตเพิ่มจากแหล่งอื่น (เช่น ขอจาก กกต. จังหวัดโดยตรง)
